# RK3568 音视频网关与 Qt 考勤控制台协作边界

## 1. 优先级

RK3568 音视频边缘网关是上游媒体数据面，优先级高于 Windows Qt 人脸考勤控制台。Qt 项目是下游只读客户端；发生摄像头、RTSP、端口、分辨率、帧率、编码、板端目录、NPU 或测试时间冲突时，以网关实际实现和验收安排为准。

## 2. Qt 项目禁止操作的范围

- 不操作、重置、抢占或配置 RK3568 的 `/dev/video*`、ALSA/USB 麦克风、UVC 摄像头或 NPU。
- 不启动第二个 `rkav-gateway`，不启动第二套板端 RKNN 或其他高负载视觉推理。
- 不重启、停止、替换或修改当前网关程序、服务、摄像头参数、音频参数、RTSP 服务端参数、端口、路径或编码参数。
- 不删除或写入 `/userdata`、TF 卡、网关日志、部署包、测试证据、录像、模型、SQLite 或网关项目目录。
- 不通过 SSH、串口或其他方式修改板端文件和服务。

确实涉及这些范围时，只能向用户说明修改内容、原因、对网关的影响、中断风险和不改板端的替代方案，等待用户明确确认并由网关项目处理。

## 3. 视频源与 RTSP 契约

- 物理摄像头、麦克风均由 RK3568 网关独占。
- Qt 的 `LocalCameraSource` 只可用于本项目独立开发；联合运行和最终演示必须使用 `RtspSource`。
- 没有可用 RTSP 时，Qt 先使用本地视频文件开发 UI、识别、状态机和数据库，不能为了 Qt 测试改变板端设备状态。
- 预期最小接口为 `rtsp://<rk3568-ip>:8554/live`。RK3568 负责监听 8554；Windows Qt 只主动连接、读取，不能在 Windows 监听 8554 或启动 RTSP 服务端。
- 第一阶段目标是 H.264、1280x720、30 FPS，Qt 考勤只读取视频，可以忽略音频。
- RTSP URL 必须可配置，禁止把具体板子 IP 写死在源码中。
- 客户端必须区分“RTSP 断流”和“画面中没有人脸”。断流期间不能写考勤事件，恢复后自动继续读取。
- `/status` 是可选的后续能力，不能成为 Qt 启动的前提。

## 4. 数据与推理边界

- RK3568 NPU 由网关 RKNN YOLOv5 链路使用；Qt 项目的人脸检测、特征提取和考勤决策只在 Windows PC 执行。
- Qt 项目的 SQLite、人员资料、脸部模板、抓拍、考勤记录、CSV、日志和模型只保存在 Windows 本地应用数据目录。
- 两项目不得共享 SQLite、运行目录、模型目录或日志目录。

## 5. 当前可推进范围

可以独立完成 `IVideoSource`、`VideoFileSource`、`RtspSource` 客户端代码、连接/断流/重连状态机、Qt UI、PC 侧人脸推理、连续帧确认、冷却和签到签退状态机、本地 SQLite 事务、视频文件回归、抓拍、查询、CSV 导出和隐私隔离。

当前不把板端 RTSP 端到端联调视为可立即完成项。只有网关正式提供并验收 RTSP 地址后，Qt 才进行只读联调。
