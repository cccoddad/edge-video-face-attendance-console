# 本轮开发与演示总结

**时间范围**：2026-08-28 至 2026-09-02

**交接对象**：下一次继续维护本 Windows Qt 项目的开发者/答辩者

**范围声明**：本文只记录本 Qt 项目。整个过程中没有读取、修改、构建或运行 RK3568 网关项目，也没有操作板端摄像头、麦克风、NPU、RTSP 服务、端口、SSH、串口或文件。

## 1. 本轮完成了什么

### 1.1 可测媒体输入

- 新增 `IVideoSource`，把媒体输入统一为打开、读帧、关闭、状态和错误信息五类能力；主界面不再直接依赖 OpenCV 的 `VideoCapture`。
- 实现 `VideoFileSource`，用于选择 Windows 本地视频文件，能显示未打开、播放中、播放结束、已停止和打开失败。
- 实现 `LocalCameraSource`，只读取 Windows 本机摄像头编号（默认 `0`），用于独立开发和演示；不会枚举或访问 RK3568/Ugreen 摄像头，也不修改设备参数。
- 预留 `RtspSource`：支持可配置 URL、非法地址校验和“输入中断/等待重连”状态文本；没有真实连接 RTSP，也没有在 Windows 启动 RTSP 服务端或监听 8554。

### 1.2 人脸识别、并发与实时性

- 沿用 SeetaFace2 完成人脸检测、跟踪、特征提取和相似度比对；低于可配置阈值（默认 `0.70`）归为未知人员。
- 将 UI、视频帧和识别任务通过 Qt 信号槽隔离。送入后台的 `cv::Mat` 使用 `clone()` 深拷贝，避免采集下一帧覆盖后台正在识别的图像。
- 增加会话编号、请求编号和“同时最多一个待处理识别请求”，在停止视频或切换输入后丢弃旧结果，防止旧画面写入新会话的考勤。
- 识别默认每 `200` 毫秒最多投递一次，预览维持约 25 FPS；这叫**限流**，即只保留较新的识别机会而不让旧帧无限排队，以减轻“越运行越卡”的现象。
- 在预览图上用 `QPainter` 绘制浅绿色人脸框；识别完成后框上沿显示姓名和工号，未完成时显示“正在识别”。绘制只影响界面显示，不会修改原始摄像头帧或模型输入。

### 1.3 考勤业务闭环

- 新增 `AttendanceStateMachine`。默认同一人员连续识别 3 帧才确认；无人脸、未知人、人员变化、停止或切换来源都会清空进度。
- 新增 `AttendanceRepository`。写入使用 SQLite 参数绑定和事务；数据库升级时补充 `event_type`、`event_key`、`similarity`、`source_type` 等列，并以 `event_key` 唯一索引做数据库层**幂等**保护。
- 完成当天签到/签退状态：第一条有效事件为签到；自动签退默认需与签到相隔 4 小时；当日签到签退完成后抑制后续事件；同时保留按人员的 30 秒冷却。
- 增加“签退（确认 3 秒）”演示入口。它不会一点击就写库：当前已识别的人必须保持单人、同一身份连续识别满 3 秒；换人、无人脸、停止输入或未签到都会取消/拒绝。最终仍复用事务与唯一键。
- 完成查询、按人员/日期/事件筛选、UTF-8 BOM CSV 导出、考勤成功后的本机 JPEG 抓拍、抓拍路径回填和过期清理。SQLite、照片、抓拍、日志、CSV 均只保存在本项目的 Windows 本地数据目录。

### 1.4 注册、界面和演示体验

- 修复注册拍照：拍照前检查视频是否仍在播放且当前帧有效；成功后明确显示“已拍照，可注册”；改动工号、姓名或部门会使已有照片失效，避免错绑。
- 将注册中的人脸跟踪、特征提取改为异步信号槽，避免在 UI 线程同步等待造成“未响应”。
- 移除原课程示例中固定的“007 / 何青德 / 嵌入式软件”占位文字；它只是 UI 演示内容，不是模型识别结果。
- 现代化重构为浅色办公风：左侧实时视频输入卡片，右侧识别/注册/查询 `QTabWidget` 页面；使用白色卡片、蓝色主色、灰色辅助色与 Microsoft YaHei UI 字体。
- 将主题集中到 `Theme` 的 QSS，将页面改为 `QHBoxLayout`、`QVBoxLayout`、`QGridLayout`，减少固定坐标；在 1280×720 下完成构建后的视觉检查。
- 为打开视频、本机摄像头、停止、拍照、注册、查询、导出配置图标、Tooltip 与运行状态启用/禁用规则。

### 1.5 构建、测试和交付

- 使用 Qt 5.12.0 + MinGW 7.3、OpenCV 4.5.2、SeetaFace2 保持原有工具链。
- 维护 `scripts/build-qt5.ps1`、`scripts/run-dev.ps1`、`scripts/package-windows.ps1`，分别用于 Release 构建、开发期运行环境和 Windows 独立打包。
- 新增/扩展本地测试：视频文件输入冒烟测试、本机摄像头短时冒烟测试、考勤状态机内存 SQLite 测试、CSV 测试和抓拍存储测试。

## 2. 本轮问题与处理结果

| 问题 | 根因 | 处理结果 | 当前结论 |
|---|---|---|---|
| 启动就显示陌生人员 | 旧 UI 写死演示文本 | 移除静态人员占位，真实识别后再加载 SQLite 人员资料 | 已解决 |
| H.264 MP4 打不开 | 当前 Qt/OpenCV 构建缺少可用 H.264 解码能力 | 保留原 MP4，生成本机忽略的 MJPEG AVI 兼容副本 | 当前环境已规避 |
| 拍照/注册像卡死 | UI 线程同步等待耗时识别，且未校验有效帧 | 改为异步信号槽，补充有效帧检查和按钮状态 | 已解决主要交互问题 |
| 视频越久越卡 | 每帧识别会造成任务堆积，缩放也耗时 | 限流、单请求、快速缩放、过期结果丢弃 | 已做短时验证，需长稳量化 |
| Qt Creator 点运行崩溃 | 编译成功但运行时 DLL/模型/插件/环境变量不完整 | 用启动脚本验证，并在本机私有 `.pro.user` 补齐运行环境 | 当前电脑已解决 |
| 旧 UI 裁切重叠 | 大量 `setGeometry` 和默认字体 | 使用布局管理器、`Theme` 和最小窗口尺寸 | 已完成 1280×720 检查 |
| 自动签退不便演示 | 自动规则默认间隔 4 小时 | 增加三秒确认的手动签退，不绕过业务规则 | 自动测试完成，待完整人工回归 |

更完整、适合不同读者的说明已同步到：

- `02-项目问题汇总-通俗版.md`：现象—原因—处理—状态。

## 3. 已验证与未验证的边界

### 已验证

1. Qt 5.12/MinGW Release 构建成功。
2. 开发脚本启动和独立 Windows 打包启动成功；模型、SQLite 驱动和运行数据目录可用。
3. `VideoFileSourceSmokeTest` 覆盖读帧、播放结束、停止和打开失败；兼容 AVI 已读取 461 帧。
4. `LocalCameraSourceTest` 覆盖非法编号错误；Windows 原生与 OpenCV 探针均验证本机 0 号摄像头返回非黑画面。正式程序连续运行 `1800.342` 秒，读取 `38380` 帧，平均 `21.318 FPS`，识别请求/返回 `379/379`，运行中没有源错误。
5. 内存 SQLite 自动测试覆盖连续确认、签到、自动/手动签退、三秒边界、人员变化、无人脸、停止视频、未签到、重复抑制、抓拍路径、查询筛选和 CSV。
6. 用户已在当前电脑完成本地视频/本机摄像头预览、人员登记、识别、查询和手动签退完整人工回归，并确认负向中断场景全部成功。该证据来自现场交互，不包含个人视频、照片或数据库文件，也不提交到 Git。
7. Excel 只读打开 UTF-8 BOM CSV，中文表头正确；便携包脱离开发 PATH 启动成功，必需依赖、隐私文件、SQLite 和 SHA-256 清单检查通过。

### 尚未验证，不应夸大

1. 本机摄像头此前近黑流的确定根因，以及再次真实掉线时 2/4/6 秒延迟重连是否恢复。
2. 便携包在从未安装 Qt、OpenCV、SeetaFace 开发环境的干净 Windows 机器上的人工启动。
3. RtspSource 的真实连接、断流、重连与 UI 输入入口。
4. 任何 RK3568 H.264 RTSP 流的端到端联调。它必须在网关提供并验收只读 URL 后，按 `05-RK3568协作边界.md` 另行安排。
