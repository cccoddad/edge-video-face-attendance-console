# 项目实施记录与下一步

## 1. 项目定位与当前状态

本项目由原有的 Qt5、OpenCV、SeetaFace 人脸识别考勤示例整理而来。当前目标不是把它包装成一个独立占用摄像头的传统考勤软件，而是升级为**Windows PC 侧的人脸考勤控制台**：在 RK3568 音视频边缘网关正式提供 RTSP 视频流后，Qt 程序作为只读客户端拉流，在 PC 上完成人脸检测、特征匹配、考勤决策、人员管理、查询、抓拍和报表。

截至 2026-09-03，Windows 本地 Qt5 基线已经能够构建、运行和打包；本地视频、本机摄像头、阶段 B 考勤状态机、查询筛选、CSV 导出、本机抓拍清理、现代化界面和手动签退均已完成代码与自动化测试。本机摄像头 `#0` 已完成一次隔离的 30 分钟长稳量化回归，CSV 已由本机 Excel 只读打开验证中文编码；手动签退的三秒边界、重复抑制、换人、无人脸、停止视频和未签到场景已有自动化证据，用户随后完成真人 UI 人工回归并确认全部成功。`RtspSource` 已完成可配置 URL、地址校验和本地状态机预留，但当前 UI 不提供 RTSP 来源入口，未连接或验证任何真实 RTSP 流。RK3568 网关的 H.264/RTSP 输出尚未验收，因此板端端到端联调不在当前可完成范围内。

## 2. 已完成的实施操作

### 2.1 基线梳理与环境确认

- 确认现有开发环境可使用 **Qt 5.12.0 + MinGW 7.3 64 位**，不需要为了本项目立刻安装 Qt6。
- 确认原项目依赖课程资料中提供的 **OpenCV 4.5.2** 和 **SeetaFace2**；当前工程仍沿用这套可验证的 SDK，而不是在未验证兼容性的情况下替换算法库。
- 将工程目标名称调整为 `FaceAttendance`，并保留 Qt Widgets、Qt SQL、OpenCV 与 SeetaFace 的现有技术路线。
- 初始化 Git 仓库并配置忽略规则，避免构建目录、运行数据、打包目录和机器私有依赖配置进入版本控制。

### 2.2 第三方依赖可构建化

原资料的目录包含中文路径，老版本 MinGW/qmake/第三方库在此类路径下稳定性较差。为降低路径编码风险，已建立仅供本机使用的 `D:\qtdeps` 依赖入口，并通过不纳入版本控制的 `src/third_party.pri` 指向它。

工程中保留 `src/third_party.pri.example`，新机器只需按示例填写依赖根目录，不会把个人磁盘路径写死到工程文件。该处理不复制或修改原始课程依赖包。

### 2.3 配置与数据目录治理

新增 `src/appconfig.h` 和 `src/appconfig.cpp`，集中管理以下运行参数：

- `FACE_ATTENDANCE_DATA_DIR`：SQLite、照片和运行数据目录；默认落在 Windows 用户目录下的应用私有位置。
- `FACE_ATTENDANCE_MODEL_DIR`：SeetaFace 模型目录；不再依赖原先硬编码的 `C:/SeetaFace`。
- `FACE_ATTENDANCE_SIMILARITY_THRESHOLD`：人脸相似度阈值，默认 `0.70`。
- `FACE_ATTENDANCE_COOLDOWN_SECONDS`：同一人员的考勤冷却时间，默认 `30` 秒。
- `FACE_ATTENDANCE_CONFIRMATION_FRAMES`：连续识别确认所需帧数，默认 `3`，范围为 `1` 至 `10`。
- `FACE_ATTENDANCE_MINIMUM_CHECKOUT_INTERVAL_SECONDS`：自动签退与签到之间的最小间隔，默认 `4` 小时；手动签退使用独立的 3 秒确认规则。
- `FACE_ATTENDANCE_RECOGNITION_INTERVAL_MS`：识别任务的最小投递间隔，默认 `200` 毫秒，用于避免预览长期积压。
- `FACE_ATTENDANCE_SNAPSHOT_RETENTION_DAYS`：本机 JPEG 抓拍保留期，默认 `30` 天，范围为 `1` 至 `3650` 天。
- `FACE_ATTENDANCE_LOCAL_CAMERA_INDEX`：Windows 本机摄像头编号，默认 `0`，范围为 `0` 至 `15`；仅用于 Qt 独立开发。
- `FACE_ATTENDANCE_RTSP_URL`：未来 RTSP 只读客户端 URL，默认空值，不提供或硬编码任何 IP。
- `FACE_ATTENDANCE_RTSP_RECONNECT_INTERVAL_MS`：未来 RTSP 断流后的重连等待时间，默认 `3000` 毫秒，范围为 `500` 至 `60000` 毫秒。

程序启动时会检查 `fd_2_00.dat`、`pd_2_00_pts5.dat`、`fr_2_10.dat` 三个必要模型，并在缺失时给出明确模型目录提示。

### 2.4 人脸识别和考勤逻辑修复

对原示例中影响可靠性的部分进行了收敛：

- 识别线程接收摄像头帧时使用克隆后的 `cv::Mat`，避免 UI/采集线程复用缓冲区导致异步识别读到无效画面。
- 匹配结果增加阈值判断，低相似度人员统一按未知人员处理，不再把“数据库中分数最高的人”直接认定为识别成功。
- 考勤写入采用预编译 SQL 和事务；注册、考勤等用户输入不再通过字符串拼接生成 SQL。
- 修复原考勤时间字段命名不一致的问题，统一按实际数据库字段 `checktime` 写入和查询。
- 增加同一人员的冷却控制，降低连续帧重复写入签到记录的概率。
- 退出时等待识别工作线程结束，减少窗口关闭后仍访问对象的风险。

### 2.5 构建、运行与发布流程

新增可重复脚本：

- `scripts/build-qt5.ps1`：使用本机 Qt5/MinGW 构建 Release 程序。
- `scripts/run-dev.ps1`：配置开发期 DLL、模型和独立运行数据目录后启动程序。
- `scripts/package-windows.ps1`：复制 Qt、MinGW、OpenCV、SeetaFace、SQLite 插件及模型文件，生成独立 Windows 发布目录。

已完成的验证包括：

1. Release 版本成功构建，生成 `FaceAttendance.exe`。
2. 在开发环境下启动成功，模型与 SQLite 初始化路径可用。
3. 将程序放入独立发布目录后，在不依赖 Qt Creator 的环境中启动验证；Qt 平台插件、SQLite 驱动、OpenCV 和 SeetaFace DLL 均已被纳入打包清单。

### 2.6 与 RK3568 网关的协作定位

已完成架构决策，不在 Qt 项目中重复建设网关能力：

- RK3568 网关是上游媒体数据面，独占 UVC 摄像头、USB 麦克风、RKNN YOLOv5 链路与板端媒体资源。
- Qt 项目是 Windows 侧下游业务控制台，只读取后续验收通过的 RTSP 视频流。
- 人脸检测、特征提取、考勤决策和 SQLite 写入只在 Windows PC 执行。
- Qt 运行数据、人员资料、模型、抓拍、报表和日志必须留在 Windows 自己的应用数据目录，不能与网关共享。

强制协作边界见 `05-RK3568协作边界.md` 和 `.cursor/rules/rk3568-collaboration-boundary.mdc`。

### 2.7 本地视频媒体输入（阶段 A）

- 新增 `IVideoSource`，以 `open`、`read`、`close`、状态、错误信息和显示名称统一媒体输入边界，UI 不再直接持有 `cv::VideoCapture`。
- 新增 `VideoFileSource`，只读取用户选择的 Windows 本地视频文件；使用现有 OpenCV 自动选择可用本地解码后端，支持播放结束状态，并预留循环播放开关，默认不循环。
- 新增 `LocalCameraSource`，仅通过 Windows 本机摄像头编号打开本机设备，不枚举或访问 RK3568/Ugreen 摄像头，也不写入设备参数。主界面提供“打开本机摄像头”，默认编号为 `0`，可通过 `FACE_ATTENDANCE_LOCAL_CAMERA_INDEX` 配置。打开、读取中断和设备被占用时均会显示明确错误。
- 主界面不再自动打开默认摄像头。新增“打开视频”“打开本机摄像头”“停止视频”与状态栏，能够显示未打开、播放中、已停止、播放结束和打开失败状态。
- 停止、播放结束或打开失败时会暂停新的识别投递；视频会话编号会丢弃切换前的异步识别结果，避免过期帧在新输入中写入考勤。
- 已执行 `scripts/build-qt5.ps1` 完成 Qt 5.12/MinGW Release 构建。新增 `tests/VideoFileSourceSmokeTest.pro`，使用 `runtime-data/test-media/local-face-fixture.avi` 验证 30 帧读取、播放结束、停止和打开失败状态；界面播放以及已注册人员的识别/SQLite 全链路回归待补充。
- 为可重复的 Windows 启动测试增加可选环境变量 `FACE_ATTENDANCE_TEST_EXIT_AFTER_MS`；仅在显式设置非负毫秒值时自动退出，不影响正常用户启动。
- 已新增 `tests/LocalCameraSourceTest.pro`：无硬件参数时验证非法摄像头编号会进入错误状态；在本机 `0` 号摄像头上完成一次打开、读帧、释放的短时冒烟验证。该测试不会保存画面或修改摄像头参数。

### 2.8 考勤业务状态机和数据闭环（阶段 B）

- 新增 `AttendanceStateMachine`。同一员工需连续 `N` 次识别结果通过阈值才生成一次确认；`FACE_ATTENDANCE_CONFIRMATION_FRAMES` 可配置，默认 `3`，范围为 `1` 至 `10`。无人脸、未知人员、视频停止或切换视频时会清空确认进度。
- 识别线程改为每个“当前恰有一张人脸”的有效帧参与确认，并限制为同时最多一个待处理识别请求，避免队列积压。请求编号会丢弃无人脸/切换视频之前的异步结果。
- 新增 `AttendanceRepository`，启动时向既有 `recorduser` 表非破坏性补充 `event_type`、`event_key`、`similarity`、`source_type` 列，并创建 `event_key` 唯一索引。所有查询和写入继续使用绑定参数；插入放在 SQLite 事务中。
- 当天第一条确认事件为“签到”；已签到后，默认间隔 `4` 小时才允许“签退”（可由 `FACE_ATTENDANCE_MINIMUM_CHECKOUT_INTERVAL_SECONDS` 配置）；完成签到和签退后，当天后续事件会被抑制。`event_key` 再提供数据库层的幂等保护。
- 保留原有 `FACE_ATTENDANCE_COOLDOWN_SECONDS`（默认 `30` 秒）作为 UI 层按人员确认冷却，避免反复离开/进入画面造成不必要的数据库操作。
- 主界面新增考勤状态栏，显示连续确认进度、签到/签退成功、冷却/业务抑制，以及红色的数据库失败提示；失败同时写入 Qt 日志。
- 新增 `tests/AttendanceStateMachineTest.pro`，使用内存 SQLite 验证连续 3 帧确认、签到、短间隔抑制、签退、当日完成后抑制，以及最终仅两条记录。测试退出码为 `0`。
- 查询页的考勤模式新增工号、开始日期、结束日期与签到/签退筛选；SQL 使用绑定参数，避免把筛选输入拼入查询字符串。人员数据模式保留原有整表查询。
- 新增 `AttendanceReport`，以与界面相同的参数化筛选查询导出 CSV。文件使用 UTF-8 BOM，目标路径由用户在 Windows 本地选择，默认位于应用数据目录；不向网关或共享目录写入数据。
- 新增 `tests/AttendanceReportTest.pro`，使用内存 SQLite 验证工号、日期和事件类型筛选，以及 UTF-8 BOM CSV 的表头、数据行和排除未筛选数据。测试退出码为 `0`。
- 新增 `SnapshotStore`。签到或签退事件事务提交后，保存对应的本地视频帧到 `FACE_ATTENDANCE_DATA_DIR/snapshots/yyyy-MM-dd`；文件名使用时间和事件键的 SHA-256 摘要，不写入姓名或工号。随后以参数化 SQL 事务回填 `snapshot_path`。图片保存或回填失败会在 UI 和日志中明确提示，但不会撤销已经提交的考勤事件；回填失败时会删除刚写出的无归属图片。
- 启动时只扫描 Qt 自己的 `snapshots` 目录，按文件修改时间清理超过保留期的 `.jpg` 文件，不访问网关、摄像头或外部目录。
- 新增 `tests/SnapshotStoreTest.pro`，在 Git 忽略的本机测试数据目录中验证 JPEG 写入与可读性、过期清理和非法保留期拒绝。`AttendanceStateMachineTest` 同时覆盖 `snapshot_path` 的事务回填；两项测试退出码均为 `0`。

### 2.8.1 本地视频注册交互修复

- 注册拍照现在检查本地视频是否仍在播放、当前帧是否有效；视频已结束时会明确提示重新打开视频，而不是生成空照片并在后续注册时失败。
- 注册窗口在成功保存当前本地视频帧后，拍照按钮会明确显示“已拍照，可注册”；工号、姓名或部门任一字段变化后会使该照片失效并恢复“拍照”，避免照片与人员信息错绑。
- 连续确认提示现在以要求帧数为上限显示，例如确认完成后保持 `3/3`，不再出现 `54/3` 这类误导性的进度文字。
- 人脸跟踪和特征注册均改为 Qt 异步信号槽。UI 线程不再同步等待识别线程，注册期间按钮显示“正在注册...”，结果返回后再写入 SQLite，降低 Windows 显示“未响应”的风险。
- `scripts/run-dev.ps1` 为本机开发设置 `FACE_ATTENDANCE_LOCAL_VIDEO_LOOP=1`，使本地视频循环播放，方便注册拍照；发布版默认不循环。注册页标题字号已调整，避免在 320 像素侧栏中被截断。
- 已确认某些 H.264 MP4 可由本机 Python/OpenCV 读取，但当前 Qt 绑定的 OpenCV 4.5.2 无法解码。对本机授权视频生成 Git 忽略的 `authorized-face-compat.avi`（MJPEG AVI）后，项目自己的 `VideoFileSourceSmokeTest` 已读完 461 帧；原 MP4 保留不修改。主界面已移除原课程示例的“007 / 何青德 / 嵌入式软件”静态占位文字，启动时显示未识别状态。

### 2.9 RTSP 客户端预留（未连接板端）

- 新增 `RtspSource`，继承既有 `IVideoSource`。它只接受带 `rtsp` 协议和主机名的 URL，使用 OpenCV 的客户端解码接口；没有默认地址，也没有在源码中写入 RK3568 IP。
- 扩展视频状态为“视频输入中断”和“正在重连视频输入”。读取中断后会等待可配置的时间再尝试连接；该逻辑的实际网络行为尚未验证，且主界面当前没有切换到 RTSP 的入口，所以本机开发路径仍是 `VideoFileSource`。
- 新增 `tests/RtspSourceTest.pro`，只验证环境变量读取、URL 校验、非法 URL 的错误状态和状态文本。测试不会调用合法 URL 的 `open`，没有建立 DNS、TCP、RTSP 或 8554 端口连接。

### 2.10 Qt 桌面界面现代化

- 新增集中式 `Theme`，统一应用字体为 Microsoft YaHei UI、浅色背景、白色卡片、蓝色主操作色和灰色辅助色；样式集中在 `src/theme.cpp`，不再在各业务函数分散设置颜色和字体。
- 主窗口改为响应式左右布局：左侧为视频输入卡片和媒体操作区，右侧为 `QTabWidget` 的识别、注册和查询页面。窗口最小尺寸为 `1100x640`，默认尺寸为 `1280x720`；页面切换不再依赖注册/查询窗口的绝对坐标覆盖。
- 注册页和查询页改用 `QVBoxLayout`、`QHBoxLayout`、`QGridLayout` 组织字段、操作和表格；旧对象名与槽函数保留，人员登记、查询和 CSV 导出逻辑不变。
- 视频文件、本机摄像头、停止、拍照、注册、查询和导出操作均增加 Qt 标准图标与 Tooltip；视频正在播放时自动禁用打开来源按钮并启用停止按钮，停止或错误后反向恢复。
- 识别页和注册页头像不再依赖 QSS `border-image` 路径，而是用 `QPixmap` 生成圆形预览。识别成功时读取 SQLite 人员记录的 `facepictrue` 路径，因此显示注册时保存的头像；图片无法读取时显示明确占位文字。
- 已在本机完成 Release 构建、自动退出启动检查和考勤状态机回归测试。首次 1280x720 截图发现旧 `.ui` 中的大字号字体覆盖主题，已修正后重新完成 Release 构建和启动，并完成当前窗口的交互式视觉检查；极端 DPI 和更小窗口仍需后续回归。

### 2.11 识别叠加层、预览流畅度与手动签退

- `QFaceObject` 现在将 SeetaFace 跟踪到的单人脸矩形坐标通过 Qt 信号传回主界面；主界面使用 `QPainter` 在显示画面上绘制浅绿色人脸框。识别完成后，框上沿显示“姓名 + 工号”；识别尚未完成时显示“正在识别”。绘制只作用于显示用 `QPixmap`，不改变摄像头画面、模型输入或原始帧。
- 识别任务新增 `FACE_ATTENDANCE_RECOGNITION_INTERVAL_MS` 配置，默认 `200` 毫秒，范围 `100` 至 `1000` 毫秒。视频预览维持约 25 FPS，而跟踪/比对最多每秒 5 次投递，且显示缩放改用快速模式，避免识别线程持续占用 CPU 导致预览越运行越滞后。这个值可按机器性能调整，但不改变摄像头设备参数。
- 识别页新增“签退（确认 3 秒）”按钮。它只会在视频正在播放且当前画面已识别到登记人员时启用；点击后固定候选工号，人员必须保持单人正脸且持续识别为同一人满 3 秒，才调用 `AttendanceRepository::recordCheckOut` 写入签退。无人脸、陌生人、识别失败、切换人员、停止视频或切换来源会立即中断本次确认。
- 手动签退会先检查当天是否已有签到；未签到和已签退均会被 SQLite 业务规则抑制。真正写入仍复用参数化 SQL、事务与 `event_key` 唯一索引，并保留本机抓拍回填。原有自动签到/签退时间间隔规则不被删除。

- 主界面新增“RTSP 视频”按钮，并与“RTSP 配置”分离。程序启动不会自动连接；只有配置通过且当前没有其他活动视频源时按钮才可用，用户显式点击后才创建 `RtspSource` 并调用只读 `open`。主界面事件只使用脱敏后的显示名，不记录用户名或密码。
- 修复来源轮询策略：此前定时器只在 `Playing` 或 `Reconnecting` 时继续，`RtspSource` 首次读帧失败实际进入 `Interrupted`，主窗口会立刻停止定时器，导致已安排的重连永远没有机会执行。现在 `Playing`、`Interrupted`、`Reconnecting` 都继续轮询，其他终止状态停止。
- 断流进入 `Interrupted`/`Reconnecting` 时，主窗口立即暂停识别，作废未返回的识别和跟踪请求，清空人员、人脸框、连续确认及三秒手动签退进度；恢复到 `Playing` 后才重新允许识别。这样不会用断流前的过期结果写入考勤。
- `RtspSourceTest` 新增轮询策略边界，验证三个可恢复状态继续轮询、四个终止状态停止。2026-09-03 Qt 5.12/MinGW Release 构建成功；8 项 Release 自动化测试全部通过；在设置现有 SeetaFace 模型目录、清空自动视频/摄像头/RTSP URL 后，程序无界面启动 3000 毫秒并以退出码 `0` 正常结束。
- 一次启动检查遗漏 `FACE_ATTENDANCE_MODEL_DIR`，程序按设计进入模型缺失错误弹窗；Qt 5.12 offscreen 平台在显示该模态弹窗时以 `0xC0000005` 退出。GDB 调用栈定位到 `QMessageBox::critical`，补齐与 `scripts/run-dev.ps1` 相同的模型目录后复测通过，因此该次失败属于测试环境配置错误，不作为 RTSP 代码崩溃结论。
- 本轮测试没有提供合法 RTSP URL，没有执行 DNS、TCP、RTSP、端口探测或监听，也没有读取或操作 RK3568。真实首次连接、读取超时、断流重连、恢复画面、解码兼容性和识别延迟均未验证；主线程内的 OpenCV `open/read` 在真实网络条件下是否造成界面等待也未验证。

## 4. 下一步实施顺序

### 阶段 A：本地媒体驱动的可测输入

1. 已定义 `IVideoSource`：统一 `open`、`read`、`close`、状态和错误信息，不让 UI 直接依赖 OpenCV `VideoCapture`。
2. 已实现 `VideoFileSource`：支持本地 MP4/AVI 等文件、播放结束状态与默认关闭的循环开关。
3. 已实现 `LocalCameraSource`：仅用于本机独立开发，支持可配置设备编号、打开失败和读取中断状态；测试已验证本机 `0` 号摄像头的一帧读取和释放。
4. 已用本地测试视频和本机摄像头完成人工演示回归；下一轮补充固定时长、固定场景的帧率、CPU、内存和识别延迟记录。

验收标准：拔掉或不接摄像头时，仍能从本地视频完整走通识别、人员查询和考勤记录流程；本机摄像头仅作为独立开发输入，程序退出无工作线程残留。

### 阶段 B：考勤业务状态机和数据闭环

1. 已实现“连续 N 帧识别成功才确认”的去抖逻辑。
2. 已将冷却时间、当天签到/签退状态和事件幂等键纳入状态机与 SQLite 唯一索引。
3. 已为确认事件保存时间、人员编号、置信度、来源类型和抓拍路径；抓拍仅保存到 Windows 应用私有数据目录，并在启动时执行可配置保留期清理。
4. 已增加按人员、日期、状态查询和 CSV 导出；对 SQL 写入失败给出 UI 可见错误。

当前验证：内存 SQLite 自动化测试已覆盖确认、签到、签退、幂等抑制、抓拍路径回填、筛选和 CSV 内容；抓拍存储测试已覆盖 JPEG 写入、可读性、过期清理和保留期校验。本机视频源冒烟测试可读取 30 帧并正确结束。已在已登记人员的视频/本机摄像头画面中完成真人 UI、SeetaFace 识别、真实 SQLite、手动签退与查询回归；CSV 也已由本机 Excel 正确解码。自动化与人工证据范围见 2.18。

### 阶段 C：RTSP 客户端适配，但不启动板端联调

1. 已将 `RtspSource` 接入 Qt 主界面的显式“RTSP 视频”入口；URL 与重连等待时间可配置，没有硬编码 RK3568 IP，启动时不会自动连接。

4. 已完成 URL 配置和非法地址状态的纯本地单元测试；仍需在不访问开发板的可控模拟输入中验证打开失败、读取超时和恢复路径。不会在 Windows 启动 RTSP 服务端或监听 8554 端口。

验收标准：可从配置加载任意 RTSP URL；模拟打开失败、读取超时和恢复后，UI 状态与事件写入符合预期。
