# 项目理解与下一步执行计划

> 状态复核日期：2026-09-26。本版修订取代 2026-09-03 的初稿；初稿中"8 项测试""RTSP 未连接真实流"等描述已过时，以本版和 `01-项目实施记录与下一步.md` 为准。

## 1. 项目全景理解

### 1.1 项目定位与架构
本项目是一个基于 Qt 5、OpenCV 和 SeetaFace 的 **Windows 人脸考勤控制台**，定位为 RK3568 音视频边缘网关的**下游只读业务客户端**。

**架构示意图**：
```
RK3568 网关（上游媒体数据面）
├── 摄像头采集（UVC）
├── 音频处理（USB 麦克风）
├── NPU 推理（RKNN YOLOv5）
└── RTSP 流输出（rtsp://<rk3568-ip>:8554/live）
         ↓ 只读拉流
Windows Qt 控制台（下游业务客户端）
├── 视频输入抽象（IVideoSource：本地视频 / 本机摄像头 / RTSP）
├── 人脸检测（SeetaFace）+ 质量门控（FaceQualityPolicy）
├── 特征匹配（SeetaFace，CPU 推理单次约 400ms）
├── 考勤决策（AttendanceStateMachine）
├── 人员管理（SQLite，DatabaseMigration 版本化）
├── 查询与报表（CSV 导出）
└── 抓拍存储（JPEG）
```

**线程模型（4 线程）**：UI 线程（界面与决策）｜`VideoSourceWorker`（视频源打开/读帧/关闭）｜`QFaceObject`（检测/跟踪/质量/识别）｜`AttendanceWriter`（考勤写入与抓拍，独立 SQLite 连接）。

### 1.2 核心技术栈
- **Qt 5.12.0 + MinGW 7.3**：Windows 下的 C++ 图形界面工具链
- **OpenCV 4.5.2**：图像处理（本机构建无 FFMPEG 后端，故 RTSP 走独立 ffmpeg 子进程）
- **SeetaFace2**：人脸识别引擎（检测/跟踪/质量/特征）
- **FFmpeg（子进程）**：RTSP 解码为 BGR 原始帧管道
- **SQLite**：本地考勤与人员数据库
- **MediaMTX / ZLMediaKit**：本机回环与跨机联调用的 RTSP 流媒体服务器（仅测试用）

### 1.3 项目边界
**必须遵守的规则**：
1. 不操作 RK3568 的摄像头、麦克风、NPU、端口、服务或文件（2026-09-04 授权为特定例外，需用户再次确认才动）
2. 不在 Windows 上启动 RTSP 服务端或监听 8554 端口（本机 MediaMTX 仅用于开发测试，使用独有端口）
3. RTSP URL 必须可配置，禁止把 IP 写死在源码中
4. 所有数据保存在 Windows 本地应用目录，不与网关共享

## 2. 当前完成状态（截至 2026-09-26）

### 2.1 已完成并验证的能力

#### A. 媒体输入抽象层
**专业术语解释**：`IVideoSource` 是一个接口类，定义了统一的视频输入边界，让 UI 不再直接依赖 OpenCV 的 `VideoCapture`。

- **IVideoSource**：抽象基类，定义 `open()`、`read()`、`close()`、状态与错误信息
- **VideoFileSource**：本地视频文件读取，支持播放结束状态
- **LocalCameraSource**：Windows 本机摄像头读取（含 30 分钟长稳历史证据、黑帧自动重开与延迟重连）
- **VideoSourceWorker**：视频源创建/读取/关闭整体移入独立工作线程，UI 线程不再阻塞在 OpenCV 读帧上
- **RtspSource**：**已实现并验证**——独立 `ffmpeg.exe` 子进程解码（`-rtsp_transport tcp → rawvideo/bgr24`），首帧 6 秒超时判定、10 秒无数据看门狗、3 帧缓冲上限、断流检测与按间隔自动重连

#### B. RTSP 拉流与联调（本机 + 跨机）
**专业术语解释**：RTSP（Real Time Streaming Protocol）是实时流协议；本地回环必须采用"推流端 → 独立流媒体服务器 → 拉流端"拓扑，因为 FFmpeg 的 muxer 不能 listen。

- 本机 MediaMTX 回环集成测试 `RtspSourceLoopbackTest`：连接、拉 30 帧、断流检测、自动重连恢复，9/9 断言
- 跨项目 PC 端到端（2026-09-13）：VM 网关推流 → ZLMediaKit → Windows 控制台拉流 415 帧；夹具跨机识别 30 次请求/29 次返回
- RTSP 长稳回归脚本参数 `-RtspUrl`（2026-09-26）：本机回环 2 分钟 1158 帧、423/422 识别请求/返回、退出码 0

#### C. 人脸识别与考勤状态机
- 连续帧确认（默认 3 帧）、按人冷却（30 秒）、`event_key` 唯一索引幂等
- 签到/签退状态机：自动签退最小间隔、手动 3 秒确认签退、当日完成后抑制
- 质量门控 `FaceQualityPolicy`：识别流程拦截亮度/尺寸/清晰度，注册流程额外要求姿态
- 考勤决策与写入分离在 4 线程模型中，SQLite 参数化 SQL + 事务

#### D. 数据与报表
- `DatabaseMigration` 版本化迁移（`schema_version` 表）
- 运行事件持久化 `runtime.log`、性能 CSV（含 P95/预览与识别 FPS/写入失败率、来源状态强制采样）
- 人员 CSV 批量导入导出、考勤筛选与 UTF-8 BOM CSV 导出（Excel 实测解码）

#### E. 构建、测试与打包
- `scripts/build-qt5.ps1` Release 构建；`scripts/package-windows.ps1` 独立打包（支持输出目录隔离）
- `scripts/run-tests.ps1` **16 项自动化测试全部通过**（2026-09-26 复核构建为最新）
- 便携包本机隔离验证通过（`verify-windows-package.ps1`）；干净机器人工验收待执行

## 4. 风险与注意事项

### 4.1 技术风险
1. **摄像头驱动**：SunplusIT 驱动下曾出现近黑流与设备短暂消失，根因未定位
2. **RTSP 兼容性**：不同服务器实现有差异（MediaMTX 需 `paths: all_others:`；拉流端等关键帧，推送端 GOP 必须小）
3. **SeetaFace CPU 推理**：单次约 400ms，是识别延迟主体，模型固有开销

### 4.2 协作边界（来自 `05-RK3568协作边界.md`）
- 不操作 RK3568 摄像头、麦克风、NPU、端口、服务或文件
- 不在 Windows 上启动 RTSP 服务端供生产使用；不监听 8554
- RTSP URL 可配置，禁止硬编码 IP
- 断流期间暂停识别，不写考勤事件

### 4.3 验证要求
每次变更后：运行相关自动化测试 → 执行启动检查 → 记录验证证据 → 更新文档状态；未验证能力直接写"未验证"。

## 5. 专业术语表

| 术语 | 解释 |
|------|------|
| **Qt** | 跨平台 C++ 图形用户界面应用程序开发框架 |
| **OpenCV** | 开源计算机视觉库，用于图像处理和视频分析 |
| **SeetaFace** | 中科视迹人脸识别引擎，提供检测、跟踪、特征提取功能 |
| **RTSP** | Real Time Streaming Protocol，实时流协议 |
| **FFmpeg** | 音视频编解码工具集，本项目用其可执行文件子进程解码 RTSP |
| **RK3568** | 瑞芯微四核 ARM 处理器，常用于边缘计算网关 |
| **MPP** | Media Process Platform，瑞芯微媒体处理平台 |
| **NPU** | Neural Processing Unit，神经网络处理单元 |
| **SQLite** | 轻量级关系型数据库，嵌入式应用常用 |
| **幂等** | 多次执行同一操作产生的结果与执行一次相同 |
| **状态机** | 描述对象状态转换的数学模型 |
| **参数化 SQL** | 使用绑定参数防止 SQL 注入的查询方式 |
| **事务** | 数据库操作的基本单位，确保原子性、一致性、隔离性、持久性 |
| **P95** | 95% 的样本都不差于该值的延迟分位数，反映尾部卡顿 |
| **GOP** | 视频编码中两个关键帧之间的间隔；拉流客户端要等关键帧，GOP 过大会导致起播慢 |
